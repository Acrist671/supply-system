# Система снабжения

Курсовой проект по дисциплине «Технологии программирования». Система помогает отделу снабжения учитывать товары на складе и в магазинах, оформлять и выполнять заявки, просматривать движения товаров и сводку по магазинам. В приложении предусмотрены роли администратора, оператора и пользователя с доступом только для просмотра.

Проект написан на Java 17 (без использования Spring Boot, для облегчения сервера): настольный интерфейс использует Swing, локальный сервер предоставляет HTTP API, данные хранятся в PostgreSQL. Схема базы данных создаётся миграциями Flyway.

Исходный код разделён на `client` (запросы к API и экраны), `server` (обработка запросов и работа с базой) и `shared` (общие типы данных). Экраны сгруппированы по разделам внутри `client/ui`.

## Запуск

1. Установите JDK 17 или новее, Maven и PostgreSQL. Создайте пустую базу данных для проекта.
2. Скопируйте `.env.example` в `.env` в корне проекта и укажите адрес базы, пользователя и пароль в `flyway.url`, `flyway.user` и `flyway.password`.
3. Из корня проекта примените миграции командой `mvn flyway:migrate`. Её также можно запустить через окно Maven в IntelliJ IDEA.
4. Запустите `com.acrist.server.SupplySystemStart` в IntelliJ IDEA с рабочей папкой, равной корню проекта. При первом запуске сервер создаст пользователя `admin` и один раз покажет его пароль в консоли. Сохраните этот пароль. Если нужен заданный заранее логин или пароль, укажите переменные окружения `SUPPLY_ADMIN_USERNAME` и `SUPPLY_ADMIN_PASSWORD` до первого запуска.
5. Не останавливая сервер, запустите `com.acrist.client.SupplyDesktopStart` отдельной конфигурацией. Войдите под созданным администратором.

## Примечание: для использования в prod

1. Создайте отдельный Maven-проект для `client`, а `shared` выделите в общий модуль для клиента и сервера.
2. Создайте в основном проекте с сервером compose-файл для создания образа сервера
3. Проект с клиентом скомпилируйте в jar-файл
4. Теперь можете запускать образ сервера на любой машине и использовать desktop-приложения на разных машинах

По умолчанию сервер доступен только на `127.0.0.1:8080`. Другой порт задаётся переменной `SUPPLY_API_PORT`; тогда клиенту нужно указать `SUPPLY_API_URL`, например `http://127.0.0.1:8081`.

Описание запросов и примеры работы с сервером находятся в [документации API](docs/API.md).
